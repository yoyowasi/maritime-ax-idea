# 해운·항만·물류 AX 주제 비교 v1

작성·공식 웹 확인일: 2026-10-07. 개인 참가, 학업·직장 병행, 기획서 우선. **주제는 미확정이며 서비스 설계와 기대효과는 검증할 가설이다.**

## 잠정 권고

실무자 접근이 아직 확인되지 않은 상태에서는 **A: 해상 수출 SI와 Draft B/L의 승인 전 근거 대조**를 조건부 1순위로 검토한다. 한 문서쌍·한 승인 장면으로 좁힐 수 있고, 선사 공식 안내로 업무 흐름을 설명하며 합성 사례로 실패 조건을 보여주기 쉽다. 문서 AI 자체의 혁신성은 낮다. 실제 비식별 사례나 실무 검토를 얻지 못하면 현장 적합성과 효과성 근거가 약해진다.

B는 선박대리점 실무자·교대 기록을 확보할 때 우선순위가 높아진다. C는 한국 공개 조건으로 설명하기 좋지만 기존 모니터링 서비스와 직접 겹쳐 후순위다. 공개 자료는 업무의 존재와 제품 기능을 뒷받침할 뿐, 국내 목표 조직의 누락 빈도·작업시간·도입 의사를 입증하지 않는다.

A는 **같은 선적·동일 의미 필드·유효 버전**을 먼저 확인한다. 값 차이를 곧 오류로 단정하지 않고, 정상 표기 차이·발행 단계·단위·구버전을 구분한다. 최신 SI가 Draft에 아직 반영되지 않은 후보도 담당자가 확인한다. 기준 문서가 충돌하거나 추출 신뢰가 부족하면 판단을 보류한다. 최초 필드는 실무자 검토 후 확정한다.

B는 메일에 답이 없다는 이유만으로 실제 업무 미처리를 확정하지 않는다. 예정·요청·계획·실적과 행위자·버전을 구분하고 ‘회신 근거 미확인’으로 표시한다. ETA 변경 시 도선·예선을 반드시 재예약한다는 규칙은 현장 SOP 확인 전 적용하지 않는다. C도 공개 일반 요율과 개별 예약·추가 free-time 조건이 동일하다고 가정하지 않는다.

## 직접 확인한 공개 업무 근거

1. Maersk는 SI 제출 후 PDF Verify Copy 발급, 사본 승인 또는 수정·재발급 절차를 안내한다. A의 승인 직전 검토 장면은 공식 흐름에 근거한다. 한국 팀의 오류 빈도·소요시간·재작업 비용은 미확인이다. [SI 제출](https://www.maersk.com/support/faqs/how-do-i-submit-my-shipping-instructions), [사본 승인·수정](https://www.maersk.com/it-it/support/faqs/amend-or-approve-copy), [Verify Copy 수정](https://www.maersk.com/support/faqs/how-do-i-make-an-amendment-to-my-verify-copy-bill-of-lading).
2. DCSA B/L 3.0은 SI 변경·처리와 Draft Transport Document 재게시를 구분하며, 일부 항목의 변경은 Booking 절차를 거친다. 따라서 모든 필드를 SI와 기계적으로 동일 비교하지 않는다. 표준 존재는 국내 적용·빈도 증거가 아니다. [DCSA 사용자 이야기](https://dcsa.org/standards/bill-of-lading/documentation-bill-of-lading-3/bill-of-lading-3-user-stories).
3. IMO JIT 안내는 선박·항만 관계자의 정확한 시간 데이터 교환과 선석·항로·항만 서비스 가용성을 다룬다. DCSA Port Call 2.0은 예정·요청·계획·실적을 구분한다. B의 관계자 간 변경 공유 구조는 확인되지만 국내 교대 누락·메일 사용 방식은 입증하지 않는다. [IMO JIT](https://greenvoyage2050.imo.org/pdf/just-in-time-portal/), [DCSA Port Call](https://reference.dcsa.org/content/standards/releases/port-call/v2/pc-v2-purpose-and-scope).
4. Maersk 한국 수입 안내는 종류별 free-time·경과 구간·KRW 요율과 기산 기준을 구분한다. C의 조건 확인 구조에 근거가 있으나 공개 표로 개별 계약 적용·절감을 확정할 수 없다. 실제 적용 시 최신 공지·예약 조건을 다시 확인한다. [한국 수입 조건](https://www.maersk.com/de-de/local-information/asia-pacific/south-korea/import).

## 비용·효과 산식과 민감도

현재 작업량·시간·단가·예산·구매 의사에 관한 자료는 아직 확보하지 못했다. 매출·시장규모·절감률·월 비용을 숫자로 채우지 않는다. 다음은 공통 월 단위 산식이며 견적·실측 후 채운다. OCR은 페이지/건, 모델은 입력·출력 토큰 등 실제 과금단위별로 분리하고 통화도 통일한다.

- 순시간 절감(시간/월) = 사례 수(건/월) × [기존 총시간 − 도입 후 업로드·검토·수정·오탐 처리 포함 총시간](분/건) ÷ 60.
- 시간가치(원/월) = 순시간 절감(시간/월) × 조직 제공 인건비/기회비용(원/시간). 현금 절감·인원 감축과 동일하지 않다.
- 운영비(원/월) = Σ(서비스별 사용량 × 각 서비스의 실제 단가) + 저장/연계비 + 규칙 유지시간 × 시간단가 + 고정비.
- 12개월 비교(원/12개월) = 월 시간가치 × 12 − 월 운영비 × 12 − 초기 설정·교육·보안 검토비. 12개월은 비교 시나리오, 확정 운영계획은 아니다.
- 민감도는 사례 수·문서/메일 분량·오탐·업로드 마찰·단가·규칙 변경 빈도의 낮음/기준/높음을 실측·견적으로 설정한다. 검토시간이 늘면 효과가 음수일 수 있다.

C의 회피 비용은 실제 계약상 발생 가능 비용과 실행 가능한 일정이 확인될 때만 별도로 분석한다. ‘경고했으므로 요율 × 지연일 절감’으로 산정하지 않는다. 계약·법률·청구의 최종 판단은 자료 분석 범위 밖이다.

## 기획서 우선 검증과 다음 결정

1. 실무자·비식별 사례 접근 가능성에 따라 재정렬한다. 외부 문의·자료 요청은 승인 범위에서만 한다.
2. 한 장면의 현재 입력·판단·승인·예외와 행동을 바꾸는 오류/미확인 상태를 확인한다. 미실시 인터뷰 결과를 작성하지 않는다.
3. 정상 표기 차이·구버전·값 누락·원문 충돌·시간대/단위·근거 부족을 포함한 합성 사례와 정답 기준을 설계한다. 별도로 실제 비식별 사례를 검토한다. **합성 자료는 구현 논리 확인에 쓰며 실제 정확도·효과·사용성 증거를 대체하지 않는다.**
4. 수동·규칙만·AI 보조의 총시간, 중요 항목 미탐/오탐, 보류, 원문 근거 정확성, 담당자 수정량을 비교한다. 소수 사례를 업계 전체로 일반화하지 않는다.
5. 양식 2.4~2.7의 데이터 확보/기존 시스템 연계, 시범범위·일정·인력·비용, 지표, 리스크를 먼저 채운다. 메일함·TMS·선사 API의 접근권한이 있다고 가정하지 않는다. 파일 반입 방식의 개인정보·영업정보 처리, 저장기간·접근통제·저작권·모델 전송 조건도 설명한다. 대표 Track은 주제 확정 후 하나를 선택한다.
6. 구현보다 문제·근거·한 장 사용자 흐름·기존 제품 비교·역할 분담·검증·비용·도입 조건을 우선한다. 프로토타입은 기획서가 안정되고 여력이 있을 때 검토한다.

가장 중요한 사용자 질문: **“마감 전까지 실제 해운·포워딩·물류 실무자에게 업무 흐름이나 비식별 양식에 대한 피드백을 받을 경로가 있나요?”**

추천 선택: 수출 문서 담당자 접근 가능 → A, 대리점 교대 사례 접근 가능 → B, 아직 없음 → A 잠정 검토와 효과 미검증 명시. 실현·효과·문제정의가 합계80점이므로 문제·검증 근거가 선택을 크게 바꾼다. C는 기존 제품과 차별화 근거가 확보될 때 재검토한다.
